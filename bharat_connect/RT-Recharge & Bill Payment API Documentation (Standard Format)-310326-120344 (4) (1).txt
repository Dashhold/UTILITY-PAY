Authentication & Token Generation API
Overview
This API is used to authenticate the partner using the provided clientId and clientSecret.
If the credentials are valid, the system generates a token that must be sent in the Authorization
header for all subsequent API calls.

Important Notes
A generated token remains valid for 24 hours and there is a daily limit of
100 tokens.
If a new token is requested while an existing token is still active, the
currently active token will expire after 5 minutes due to the token
rotation policy. A new token will be issued with a fresh 24-hour validity
period.

1.Steps for Encryption :
Encryption Protocol Overview
For all APIs mentioned below, use Hybrid Encryption combining asymmetric and symmetric
cryptography:
/v3/retailerViewbill
/v3/retailerValidation
/v3/retailerBalance
/v3/retailerPayment
/v3/retailerStatus
RSA-2048 bits: For session key exchange (this will be provided by mobikwik over mail
subject : MobiKwik API - Your Public Key for Secure Integration)
You have to extract this public key from the pem file and use this key to encrypt your AES
session key .
AES-256-GCM: For payload encryption

Request Structure

Above API call must include an encryptedPayload in the following format.

Sample Encrypted JSON Payload :

Step 1.1: Generate AES Session Key

Generate a random 256-bit AES session key.
sessionKey = AES-256 random key
256-bit key

Step 1.2: Encrypt JSON Payload

Encrypt the actual API payload using the AES session key.
Use a random 16-byte IV (Initialization Vector).
Output the encrypted payload bytes, then Base64-encode them.
encryptedPayload = Base64( AES-256-GCM(payload, sessionKey, IV) )
Step 1.3: Encrypt Session Key with RSA

Encrypt the AES session key using RSA-2048 Public Key shared by MobiKwik (via email).
Use PKCS1Padding padding.
Output the encrypted session key bytes, then Base64-encode them.
encryptedSessionKey = Base64( RSA-2048(sessionKey, MobikwikPublicKey) )
Step 1.4: Encode Initialization Vector

Base64-encode the 16-byte IV used in AES encryption.
iv = Base64(IV)
Step 1.5: Add Metadata

Include the following metadata fields in the request:
keyVersion → provided by MobiKwik in readme.txt file in mail subject : MobiKwik API - Your
Public Key for Secure Integration
Step 1.6: Send to API Endpoint

Send the final encrypted request payload (as JSON) to the respective API endpoint.
